# 人物参考图生成

每个 `characterId` 只创建一个身份底图。不同场景下服装、妆造、湿污、伤妆或随身物发生可见变化时，以该底图为单一参考，通过图生图创建派生角色设计图。

**版式与 Prompt 真源是 `aigc-canvas:image-prompt-skill` 的角色资产任务。** 本 Skill 只负责画布节点、连线、授权门和审核；禁止在此复制旧四联骨架或自行发明 2×2 网格。

## 输入

先取得角色身份档案、场景绑定的外观版本、统一视觉风格和图片工作流。角色资料至少包括：

- 年龄段、性别表达、体型、肤色、脸型、五官、发型发色及稳定识别特征；
- 身份底图使用的基准服装，以及各场景版本的上装、下装、鞋、外套、饰品、随身物、妆造与湿污/破损状态；
- 真人、动画、三维等媒介风格，以及色彩、材质和写实程度。

资料不足时做保守补全并明确标记推断；不得擅自改变已有角色身份或服装设定。

## 提示词委派

编写或重写任何人物 `image.prompt` 前，必须读取并执行 `aigc-canvas:image-prompt-skill`：

1. 任务类型固定为 `character-assets`。
2. 未指定其他版式时，使用其默认「三大版面、四个功能区」：
   - 画布 16:9；横向约 `22% + 22% + 56%`；
   - 第 1 区正面全身 **无头无脸**，只负责身体与服装正面；
   - 第 2 区背面全身 **含后脑、不露脸**，负责背影、后脑发型和服装背面；
   - 右上中性 3/4 面部特写：主身份锚点；
   - 右下微笑 3/4 面部特写：同一人、同一角度/光线/发型/服装，只改变表情。
3. 禁止退化为头部近景+正侧背四联、普通 2×2，或把两个表情当成两个角色。
4. 写实真人必须按该 Skill 写入皮肤五变量；动漫/插画/像素不要加真人毛孔。
5. 目标为 3D、次世代二次元、3D 国漫、游戏 CG、影视 CG、虚拟偶像、半写实或高级时装 CG 时，必须读取 [references/3d-character-prompt-template.md](references/3d-character-prompt-template.md) 的风格档位与材质/渲染用语；**排版一律以本 Skill 的三大版面四功能区为准，不得改用其中的四联排版**。
6. **风格档位**：参考文件开头即确定风格档位。用户要求「3D 国漫、漫剧、次世代二次元、三维动画电影、游戏/影视 3D CG、非真人照片、非 2D 平涂」时默认走 **A 档·3D 漫剧写实厚涂 CG / 次世代二次元国漫**，重点写「3D漫剧写实厚涂风、顶尖国漫3D建模、UE5+PBR物理渲染、UE5全局光照、次表面散射、轮廓偏东方骨相、五官立体但不欧美化、东方骨相+西方人体结构融合、写实厚涂质感、次表面散射CG肌肤、有体积感蓬松发丝、有厚度垂坠服装、UE5全局光照、体积光、景深」。**必须保留并强调**「写实厚涂、次表面散射、UE5」等半写实三维词（这是用户要的质感）。同时**明确禁用**：
   - 2D 向：`三渲二、卡通渲染、卡通、扁平、平涂、2D、二维、漫画风、动漫贴图、块状头发`；
   - 照片向（像真人照片/证件照）：`真实摄影、照片级、像真实照片、证件照、超写实照片、写实到真人`——注意不要误禁「写实厚涂/次表面散射/UE5」；
   - 其他：`幼态、锥子脸、娃娃脸、欧美化轮廓、文字、水印、多人物`。
   只有用户明确要「真人、真人照片、照片级、超写实、实拍」时才走 B 档·纯真人写实。不要把「照片级真人」作为默认，也不要误把用户要的「写实厚涂/软质半写实」当成照片级真人而禁掉。
7. 参考文件中的少年男性、年龄、身高、九头身、肤色、韩系穿搭、写实材质等只是示例变量，必须由当前角色档案覆盖；不得把示例审美强加给其他性别、年龄、体型或风格。
8. 非 3D 风格不要加载该参考，继续使用本 Skill 的三大版面四功能区规范。

先合并外观完全相同的场景版本。同一角色在多个场景中服装、妆造和可见状态不变时，复用同一张底图或派生图，不重复生成。

## 资产图结构

### 身份底图

- 每个 `characterId` 只能有一个身份底图，标题使用 `角色｜身份底图｜四区设计图`。
- 身份底图使用文生图，固定角色不可变特征和基准服装；它是该角色全部派生版本的共同根节点。
- 必须先生成并审核身份底图，取得有效 `sourcePath` 后才能生成任何派生图。

### 场景派生图

- 每个不同的 `outfitId` / 可见状态版本创建一个 `image` 节点，标题使用 `角色｜场景/服装版本｜图生图四区设计图`。
- 从身份底图直接连接到每个派生节点，使图片生成动作读取底图 `sourcePath` 并自动使用图生图。派生节点只能接入这一张人物底图作为生成参考。
- 禁止从一个场景派生图继续生成另一个场景派生图；所有分支都必须直接回到身份底图。
- 派生任务仍走 `image-prompt-skill` 的图生图/角色资产路线：严格继承参考图中的脸、年龄、体型、肤色、发型和识别特征，只改变指定服装/妆造/状态，并保持同一四区版式。
- 如果某个场景外观与身份底图完全一致，直接复用身份底图，不创建派生节点。

## 版式验收（替代旧四联）

- 一张图只表现同一个角色和同一个外观版本。
- `aspectRatio` 固定为 `16:9`。
- 第 1 区不得出现头、脸或头发；第 2 区不得缺后脑，也不得转头露脸。
- 右侧两区必须是同一人、同一 3/4 朝向与光线；微笑不得改脸型或五官比例。
- 全身自然直立，不摆 A-pose、T-pose、战斗姿势。
- 纯净中性背景、统一棚拍光；无文字、标签、水印、Logo、边框或额外人物。

## 创建与生成

1. 调用 `GetCanvasCapabilities`。身份底图选择真实可用的文生图工作流；派生节点选择支持图生图的工作流，不要猜测 `workflowId`。
2. 用 `image-prompt-skill` 写出每个角色唯一身份底图的中文 Prompt，再创建节点。
3. 汇总身份底图节点、工作流和提示词摘要，明确询问是否开始生成。只有用户明确同意后才能调用 `InvokeNodeAction(generate)`；然后逐节点轮询。某个节点 `generationStatus=error` 或没有 `sourcePath` 时：只停止该失败节点及其派生图，报告节点 id 和 `generationError`；不要打断其他仍在 generating 的身份底图，重做只针对失败节点。生成动作会对该失败节点自动重试最多 3 次再切备用，不要再手动连打三次。只有 idle 且 `sourcePath` 非空的底图，才读取实际图片并审核四区职责、身份辨识度和无头/含后脑约束。不合格时说明重做范围，重新确认后再生成。
4. 底图合格后创建场景派生节点，再次调用 `image-prompt-skill` 写入图生图 Prompt，并建立 `身份底图 → 场景派生图` 连线。不得在底图尚无 `sourcePath` 时触发派生生成。
5. 展示派生节点、对应底图、场景/服装版本、图生图工作流和摘要，单独取得明确确认后生成派生图。
6. 检查每张派生图是否继承底图身份、四区仍为同一人、只发生指定外观变化。身份变化时修改派生 prompt 或回到底图修复；底图一旦替换，所有依赖它的派生版本都必须标记为待重新生成。
7. 若由其他生产 Skill 调用，返回 `characterId → baseNodeId → variantNodeIds → sceneIds` 映射和两个阶段的生成计划，由调用方统一执行授权门。
