# 场景参考图生成

为每个不同 `sceneId` 先创建一张无人基础环境底图，再以它为唯一参考生成一张可被多个视频片段复用的四宫格空间参考图。底图与四宫格分别使用一个 `image` 节点，以 `基础环境底图 → 四宫格环境图` 连线表示依赖；只有最终四宫格作为视频参考图片，占一个参考名额。场景参考图服务于空间、材质、光线和行动路线连续性，不直接充当成片构图。

## 输入与归并

先取得场景清单、成片画幅、统一视觉风格和图片工作流。每个场景档案至少包括：

- 地点、时代、用途、空间尺度、层高和主要结构；
- 正面主墙面或主要入口，以及以正面视图为基准的左侧、右侧和背面方位；室外场景以主要建筑立面或核心地标确定正面；
- 出入口、窗、走廊、楼梯、人物行动路线和关键视线；
- 固定家具、关键道具、墙地顶材质及磨损状态；
- 时间、天气、主光方向、色温、实用光源和阴影关系；
- 剧情阶段造成的布置、污染、湿润、损坏或灯光变化。

同一地点只有在布局、时间、天气、灯光或破坏状态发生可见变化时才新建版本。外观相同的场次复用同一个 `sceneId` 和节点。

## 两阶段资产结构

### 基础环境底图

- 每个去重后的 `sceneId` 创建一个无人 `image` 底图节点，标题使用 `场景｜状态版本｜基础环境底图`。用文生图建立该场景的空间身份：正面主墙面或主要入口、可辨识的布局与纵深、出入口、固定家具、关键道具、材质、时间天气和主光方向。
- 底图是单幅平视透视画面，不要求四宫格；其观察方向作为后续 Front View 的方位基准。不要生成俯视图、二维户型图、人物、文字标签或四个彼此无关的环境。
- 必须先生成并查看实际底图，确认空间可读、方位明确、关键结构和光线符合场景档案，取得有效 `sourcePath` 后才能创建或生成四宫格。

### 四宫格派生图

- 每个 `sceneId` 创建一个无人 `image` 派生节点，标题使用 `场景｜状态版本｜图生图四宫格环境图`。只把对应底图这一张图片连入派生节点，并将 `referenceImageNodeIds` 设为仅包含该底图节点 ID，确保生成时只使用这一张参考图；图片生成也会读取其他已连入的图片，不能只靠参考轨排除多余连线。
- 使用画布图片工作流时，派生节点选择支持图片编辑或参考生图的云端图片工作流。当前 ComfyUI 图片工作流仅支持文生图，不能用于这一步；不能在缺少底图输出、连线或可用参考生图能力时退化为独立文生图。
- 派生 prompt 要求严格继承底图的空间布局、出入口、家具位置、材质、天气与场景光照，只改变观察方向并排成四格。不要从已有四宫格继续派生新版本；不同可见状态建立各自底图和四宫格。

## 画面规范

- 一张图只表现一个场景版本，整体画幅与成片一致，采用 2×2 等尺寸四宫格。按从左到右、从上到下固定排列：
  - 左上 **Front View（正面视图）**：正对场景主墙面，展示主要空间特征或入口。
  - 右上 **Left View（左侧视图）**：从场景左侧向内部观察。
  - 左下 **Right View（右侧视图）**：从场景右侧向内部观察。
  - 右下 **Back View（背面视图）**：朝正面视图的反方向观察，展示背面墙或背面的环境。
- 先确定正面朝向，再固定其余三个方位；左右指以正面视图为基准的场景侧位，不是把正面图水平翻转或裁切。四格使用一致的平视相机高度和相近视野，以真实透视展示四个方向，不使用高机位俯视或垂直鸟瞰。
- 四个视角共同交代出入口、行动通道、固定家具、关键道具和空间分区；让人物将来从哪里进入、移动、停留和离开一目了然。
- 四格必须是同一空间的不同观察方向，布局、物件位置、尺度、材质、时间、天气和灯光状态一致；主光方向按场景空间固定，投影随视角自然变化，不得为每格重新布置家具、门窗或光源。
- 保持真实透视、立面和纵深，不使用等距插画、剖面图、建筑蓝图或二维户型图。
- 场景中不得出现人物、人体局部、人形模特、镜中人或可辨识角色；普通环境陈设可以保留。
- 不生成文字、标签、尺寸线、水印、Logo 或装饰边框；四格清晰分区，不增加额外视图。视图名称和顺序写入提示词，不要求图片内渲染标签。

## 创建与生成

用户明确指定 Codex CLI 生图时，调用 `aigc-canvas:codex-cli-image-generation` 执行下列两阶段的实际生图：先创建基础环境底图节点，CLI 出图后把 PNG 路径更新到该节点；底图合格后先创建四宫格派生节点，把底图 PNG 作为唯一 `-i` 参考图，CLI 出图后更新派生节点。保留底图→四宫格连线、单底图参考轨和本 Skill 的两次生成确认；此路线不调用图片节点的 `InvokeNodeAction(generate)`，也不要求选择云端参考生图工作流。

1. 调用 `GetCanvasCapabilities`。使用画布图片工作流时，分别确认真实可用的文生图工作流和支持参考图片的云端图片工作流，不猜测 `workflowId`；若缺少后者，报告阻塞，不生成无法按底图派生的四宫格。指定 Codex CLI 时按上文路线处理。
2. 为去重后的每个场景版本创建基础环境底图节点，写入中文文生图 prompt；不要把人物动作或视频运镜塞进场景图。
3. 汇总 `sceneId`、底图节点、生图方式和中文提示词摘要，明确询问是否开始生成底图。只有用户明确同意后才能开始：画布工作流调用底图的 `InvokeNodeAction(generate)` 并等待节点离开 `generating`；Codex CLI 路线按新 Skill 出图、导入节点。检查实际图片并取得有效 `sourcePath`；不合格时说明原因，重新取得明确确认后重做。
4. 底图合格后，为每个场景版本创建四宫格派生节点，写入中文图生图 prompt，建立唯一的 `底图 → 四宫格` 图片连线，并将派生节点的 `referenceImageNodeIds` 设为 `[底图节点 ID]`。生成前复核底图仍有有效 `sourcePath`，不存在其他图片入边，参考轨仅指向该底图，所选生图方式支持实际使用底图作为参考。
5. 汇总派生节点、对应底图、参考生图方式和中文提示词摘要，单独询问是否开始生成四宫格。只有用户再次明确同意后才能开始：画布工作流调用派生节点的 `InvokeNodeAction(generate)`；Codex CLI 路线按新 Skill 出图、导入节点。
6. 等待派生节点离开 `generating`，读取实际图片，对照底图检查：是否无人、是否为顺序正确的 2×2 正面/左侧/右侧/背面四宫格、四个方向是否可区分且没有重复或镜像冒充、空间是否完整可读、立面和纵深是否真实，以及四格布局/材质/光线是否继承底图并符合档案。不合格时只修改受影响节点；说明原因和重做范围，重新取得明确确认后再生成。
7. 底图一旦重做，依赖它的四宫格必须标记为待重新生成和复核；旧四宫格不得继续作为可用视频参考。若由生产 Skill 调用，返回 `sceneId → baseNodeId/baseSourcePath → gridNodeId/gridSourcePath → reusedBySegmentIds` 映射，并标明尚未生成或待重做的版本，由调用方执行两个阶段的授权门。

## 中文提示词骨架

把下列结构写成自然、具体的中文，不保留占位符：

```text
基础环境底图：无人[场景名称]，[视觉媒介与时代风格]，[成片画幅]单幅平视透视画面。正对[主墙面或主要入口]观察，清楚展示[空间布局、纵深、出入口、行动通道、固定家具和关键道具]，作为后续四视图的正面方位基准。墙地顶与家具材质为[材质]，处于[时间/天气/状态]，场景主光从[固定方向]进入，辅以[实用光源与色温]。无人、无人形、无文字标签、无水印；不用俯视图、二维户型图或四宫格。

四宫格派生图：以输入的基础环境底图为唯一空间参考，严格保留其[主墙面或入口]、[布局与行动路线]、[出入口与固定物位置]、[材质]和[时间/天气/状态及主光方向]，把同一场景转换为[成片画幅]的 2×2 等尺寸四宫格。左上 Front View（正面视图）：沿底图的正面方位观察，展示[正面可见内容]；右上 Left View（左侧视图）：从以正面视图为基准的场景左侧向内部观察，展示[左侧视角可见内容]；左下 Right View（右侧视图）：从场景右侧向内部观察，展示[右侧视角可见内容]；右下 Back View（背面视图）：朝正面视图的反方向观察，展示[背面墙或背面环境及其可见内容]。四格采用一致的平视相机高度、相近视野和真实透视，不得镜像、裁切底图冒充其他视角或重新布置空间；投影随视角自然变化。画面中无人、无人形、无文字标签、无尺寸线、无水印、无装饰边框，仅保留四格清晰分区；不使用高机位俯视、垂直鸟瞰、二维户型图、等距插画或剖面图。
```
