# AGENTS.md

本文件适用于在本仓库中工作的代码代理与自动化 Agent，包括但不限于 Codex、Claude Code、Cursor Agent、GitHub Copilot Agent 和其他具备文件修改能力的工具。

目标：在扩展 Video Prompt Skill 时，保持 Reference Architecture v2 的分层边界、单一真源、运行稳定性和可验证性。

## 1. 修改前必须阅读

开始任何修改前，按顺序阅读：

1. `SKILL.md`
2. `references/index.md`
3. 与当前任务有关的分类索引
4. 对应叶子真源
5. `docs/reference-architecture-v2.md`
6. `docs/validation-report.md`

涉及迁移、删除或大规模重构时，还必须阅读：

- `docs/migration-inventory.md`
- `docs/implementation-plan-v2.md`
- `docs/phase7-test-scenarios.md`
- `docs/phase7-regression-results.md`

不得只根据文件名猜测职责，也不得跳过现有真源直接新建重复文件。

## 2. 仓库核心架构

运行链路固定为：

```text
输入理解
→ 任务 Playbook
→ 按需控制
→ 按需资料库与风格
→ 模型适配
→ 输出合同
→ 失败时诊断
```

目录职责如下。

### `references/inputs/`

只负责：

- 判断输入模态；
- 分析素材承担什么职责；
- 提取首帧、尾帧、人物、场景、动作、声音等锚点；
- 识别素材冲突。

不得：

- 决定完整任务流程；
- 复制模型专属语法；
- 编写完整风格实现；
- 直接替代输出模板。

### `references/tasks/`

只负责：

- 判断当前是什么视频任务；
- 规定任务步骤；
- 说明需要哪些输入、控制、风格和输出模板；
- 定义任务完成条件。

不得：

- 维护大型术语表；
- 复制通用镜头、动作或风格知识；
- 写入某个模型的全部专属规则。

### `references/controls/`

只负责：

- 判断方法；
- 变量协调；
- 冲突裁决；
- 连续性和失败限制；
- Prompt 信息组装原则。

不得：

- 变成镜头、动作或表情百科；
- 复制模型适配语法；
- 按题材建立大量重复控制页。

### `references/libraries/`

只负责回答“有哪些可选项”。

包括：

- 镜头、机位、焦段和运镜；
- 动作、打击和物理反馈；
- 表情、微表情与对白表演；
- 转场和视觉特效；
- 光影与色调；
- 声音和音乐；
- 题材级节拍与组合。

不得：

- 决定任务执行流程；
- 替代 controls 的判断方法；
- 直接存放大段社区 Prompt。

### `references/styles/`

只负责说明一种风格如何通过以下变量被执行：

- 镜头；
- 表演；
- 光影；
- 色彩；
- 材质；
- 节奏；
- 声音。

不得：

- 只列风格名；
- 只写导演、品牌或作品名称；
- 复制完整镜头术语库；
- 建立与 genre patterns 重复的题材百科。

### `references/models/`

只负责：

- 模型能力边界；
- 输入与素材引用方式；
- 模型偏好的 Prompt 组织；
- 通用导演方案到目标模型的转换；
- 模型专属高风险写法；
- 来源和复核日期。

当前正式模型范围只有：

- `generic.md`
- `seedance-2.md`
- `ltx-2-3.md`

不得创建 Kling、Veo、Sora、Runway 或其他模型的空适配页。

如果用户要求未正式支持的模型，默认仍使用 Generic，除非维护者明确决定新增正式适配并完成来源核验与测试。

### `references/diagnostics/`

只在失败后读取。

每份诊断叶子必须包含：

- 失败现象；
- 常见根因；
- 检查顺序；
- 最小修复；
- 重写骨架；
- 完成标准。

一次只选择一个主诊断。不得为了覆盖所有问题同时加载全部诊断页。

### `assets/templates/`

只负责对外交付结构。

不得在模板中复制大段控制逻辑、模型知识或资料库正文。

### `research/`

用于保存：

- 用户原始资料；
- 官方资料记录；
- 社区案例；
- 来源清单；
- 提炼过程。

原始资料不得直接作为运行期 Reference。必须先完成来源核验、去重、抽象和职责拆分。

## 3. 单一真源原则

同一知识只能有一个正文真源。

允许：

- 多个索引指向同一叶子；
- task 引用 control；
- style 引用 library；
- model adapter 转换通用导演方案。

禁止：

- 在多个文件中复制同一套镜头术语；
- 在每个任务页重复完整连续性规则；
- 在每个模型页复制完整动作、表演和风格知识；
- 为了“方便阅读”复制大段正文到索引；
- 把同一题材同时建设成 task、control、library 和 style 四套正文。

发现重复内容时，优先：

1. 确定唯一真源；
2. 其余位置改成简短职责说明和链接；
3. 更新索引；
4. 补迁移记录；
5. 验证后删除旧正文。

## 4. 新需求应该放在哪一层

收到新需求时，先判断它回答什么问题。

| 问题 | 应进入的层 |
|---|---|
| 输入素材是什么、各自负责什么 | inputs |
| 当前要执行什么视频任务 | tasks |
| 为什么这样设计、变量如何协调 | controls |
| 有哪些镜头、动作、表情或声音选项 | libraries |
| 某种风格如何拍出来 | styles |
| 某个模型如何表达或有什么限制 | models |
| 生成失败的主要原因是什么 | diagnostics |
| 最终结果如何对外呈现 | templates |
| 尚未审计的原始资料 | research |

无法明确归层时，不要立即新建文件。先检查现有真源是否可以扩展。

## 5. 快速模式与交互模式不可破坏

### 快速模式

默认行为必须保持：

- 用户没有明确要求共创时自动启用；
- 零追问；
- 零人工确认；
- 自动补足低风险缺失信息；
- 直接输出可复制结果；
- 简单任务默认只输出一个最终 Prompt；
- 不默认输出备选方案；
- 不默认展示自动补全项和内部分析。

不得因为新增 Reference 而让快速模式变成问卷式工作流。

### 交互模式

只有用户明确要求讨论、脑暴、逐步设计、比较方向或 Grill Me 时启用。

必须保持：

- 每次只问一个最关键的问题；
- 同时给出推荐答案和理由；
- 已确认的信息不重复问；
- 能推断的信息不追问；
- 只剩轻微细节时立即收口。

不得设置机械固定轮数，也不得在用户要求直接出结果后继续追问。

## 6. 模型适配规则

### Generic

- 用户未指定模型时默认使用；
- 不伪造平台参数；
- 不伪造素材语法；
- 不承诺未核验能力。

### Seedance 2.0

- 模型专属素材绑定只能在 Seedance adapter 中维护；
- 每个 `@图片N / @视频N / @音频N` 必须有明确职责；
- 不得写“综合参考所有素材”；
- 视频编辑必须区分保留、修改、允许变化和禁止变化；
- 视频延长必须描述接点状态和新落点。

### LTX-2.3

- 最终默认使用流动、具体、现在时的自然语言；
- 图生视频重点写接下来如何运动；
- 抽象情绪改成身体表演；
- 对白需要动作、停顿、呼吸和视线配合；
- 避免堆叠过量机械数值。

### 模型规格更新

模型能力、素材数量、时长、分辨率或产品限制属于易变信息。

修改时必须：

1. 使用官方或一手来源；
2. 标明资料日期；
3. 标明复核日期；
4. 区分官方能力与社区实践；
5. 不把产品界面限制写成永久通用规则；
6. 更新相应测试记录。

## 7. Reference 加载预算

正常任务不得全量加载知识库。

固定读取：

- 1 份主 input；
- 1 份主 task；
- 1 份模式合同；
- 1 份主交付模板。

按需读取：

- 0–3 份 controls；
- 0–2 份 libraries；
- 0–1 份 style；
- 0–1 份 model adapter；
- 0–1 份多模态模板；
- 失败时 0–1 份 diagnostic。

新增文件不得导致默认任务必须加载更多无关 Reference。

## 8. Prompt 内容质量要求

新增或修改规则时，必须维护以下底线：

- 有清楚的初始状态；
- 主体运动与镜头运动分开；
- 动作有开始、推进、反馈和结束；
- 镜头有目的、起点、方向和停止点；
- 空间、站位、朝向、道具和光源连续；
- 多模态素材有唯一主真源；
- 情绪转换成可观察表演；
- 声音与视觉事件有明确关系；
- 光影和音效有场景来源；
- 一段视频只保留一个主镜头任务；
- 最后一拍可自然停住；
- 负向限制只针对最危险的失败模式。

不得使用大量 `cinematic`、`masterpiece`、导演名、品牌名或空泛质量词代替上述设计。

## 9. 新增文件规范

新建叶子文件前必须回答：

1. 现有真源为什么不能扩展；
2. 新文件属于哪一层；
3. 谁会路由到它；
4. 它会替代或引用哪些旧内容；
5. 是否增加加载预算；
6. 如何测试；
7. 是否需要更新迁移清单和验证报告。

文件命名应：

- 使用稳定的英文 kebab-case；
- 表达职责，不使用模糊名称；
- 与同级目录保持一致；
- 避免 `new`、`final`、`v3-final` 等临时命名。

索引必须使用相对路径指向真实存在的叶子文件。

## 10. 修改流程

建议按以下顺序工作：

1. 读取运行入口和相关索引；
2. 搜索是否已有真源；
3. 明确修改层级和影响范围；
4. 先改叶子真源；
5. 再改分类索引；
6. 必要时改 `SKILL.md`；
7. 补测试场景或回归结果；
8. 检查旧路径、重复正文和断链；
9. 更新进度、迁移或验证文档；
10. 最后进行分支差异核对。

不得先改 `SKILL.md` 再猜测叶子内容。

## 11. 测试与验证要求

本仓库是 Markdown Skill，测试分为两类。

### 结构验证

Agent 可以完成：

- 路由是否唯一；
- 路径是否存在；
- 层级职责是否正确；
- 输出合同是否匹配任务；
- 模型是否正确分流；
- 是否存在重复真源；
- 是否仍引用旧路径；
- 删除后是否断链；
- 快速和交互模式是否保持行为约束。

### 外部模型实测

没有真实模型执行能力时，不得宣称完成：

- 人脸稳定率验证；
- 手部和接触成功率验证；
- 复杂动作质量验证；
- Seedance 编辑和延长效果验证；
- LTX 口型和同步音频质量验证；
- 实际分辨率、时长和产品端限制验证。

必须明确写成“结构验证通过，外部模型效果待实测”。

### 回归场景

重大改动至少检查 `docs/phase7-test-scenarios.md` 中相关场景。

新增新的输入、任务、模型或诊断能力时，必须增加对应测试场景和结果记录。

## 12. 删除与迁移规则

删除文件前必须同时满足：

- 新真源已经存在；
- 有效知识已经迁移；
- 分类索引已指向新真源；
- `SKILL.md` 不再引用旧路径；
- 静态回归通过；
- 删除不会产生断链；
- 迁移清单有明确记录。

不得批量删除尚未逐份核对的文件。

原始资料原则上保留在 `research/incoming/` 以便追溯，不与旧运行文件一起删除。

## 13. 文档同步要求

根据修改范围更新：

- 用户使用方式变化 → `README.md`
- Agent 维护规则变化 → `AGENTS.md`
- 运行入口变化 → `SKILL.md`
- 总路由变化 → `references/index.md`
- 分类叶子变化 → 对应分类 `index.md`
- 架构变化 → `docs/reference-architecture-v2.md`
- 迁移变化 → `docs/migration-inventory.md`
- 测试变化 → `docs/phase7-test-scenarios.md` / 回归结果
- 最终结论变化 → `docs/validation-report.md`
- 模型资料变化 → `research/source-manifest.md` 和对应 adapter

不得只改正文而不更新导航与验证文档。

## 14. 提交规范

推荐使用清晰的提交前缀：

- `feat(inputs): ...`
- `feat(tasks): ...`
- `feat(controls): ...`
- `feat(libraries): ...`
- `feat(styles): ...`
- `feat(models): ...`
- `feat(diagnostics): ...`
- `docs: ...`
- `refactor: ...`
- `test: ...`
- `chore: ...`

一次提交尽量只解决一个职责明确的问题。

不得在没有验证记录的情况下把大规模重构描述为“fully validated”。

## 15. 严禁事项

- 禁止绕过 `SKILL.md` 和索引直接建立平行运行入口；
- 禁止复制同一知识到多个正文文件；
- 禁止把社区长 Prompt 原样放入运行期 Reference；
- 禁止把社区实践描述成官方能力；
- 禁止创建未核验模型的空适配器；
- 禁止让快速模式默认追问；
- 禁止让交互模式一次问多个问题；
- 禁止默认输出主版本、备选 A、备选 B；
- 禁止默认暴露内部分析和自动补全过程；
- 禁止使用大量负向词代替结构修复；
- 禁止一次性加载整个 Reference 目录；
- 禁止虚报外部模型实测结果；
- 禁止删除原始来源追溯信息；
- 禁止在未检查断链时删除旧文件。

## 16. 完成定义

一次修改只有同时满足以下条件才算完成：

- 内容进入正确分层；
- 不产生重复真源；
- 所有路径真实存在；
- 索引和运行入口已同步；
- 快速 / 交互模式行为未被破坏；
- 模型边界没有被擅自扩大；
- 相关测试或静态回归已记录；
- 文档和迁移状态已同步；
- 未把结构验证冒充模型实测；
- 分支差异符合预期。
