# Image To Video Playbook

## 1. 适用范围

用户以一张或多张图片作为首帧、尾帧、人物、场景、关键帧或分镜参考，并希望生成视频时读取本页。

输入 Reference：

- 单张图片：`inputs/single-image-input.md`
- 多张图片：`inputs/multi-image-input.md`

如果同时提供视频或音频，优先进入 `multimodal-reference-video` 任务。

---

## 2. 核心目标

图生视频的重点不是把图片当小说重写，而是：**全局锁一次首帧继承项，再从当前状态可信地开始运动。** 默认生产单元是 15 秒，不写 20–30 秒计划。

```text
首帧继承清单（只写一次）
→ 当前状态 / 动作中点
→ 起始微动作或直接接续
→ 主体核心运动
→ 镜头跟随或观察
→ 环境响应
→ 15 秒内的最终状态
```

## 4. 执行流程

### 4.1 识别图片职责

先使用输入 Reference 判断：

- 首帧从哪里开始；
- 尾帧要抵达哪里；
- 人物、服装、场景和风格分别由谁提供；
- 多图之间是否存在冲突。

### 4.2 提取视频锚点

只保留影响连续性的关键内容：

- 人物身份和服装；
- 当前姿态和重心；
- 场景主结构和道具位置；
- 镜头位置和构图；
- 光源方向和色调；
- 视觉媒介和材质。

### 4.3 设计起始运动

先看图片是静止开场还是动作中点。

**画面已是接触、失衡、腾空、格挡中途：**

- 把该姿态当作第 0 秒动作中点；
- 立即按受力方向和未完成动作接续；
- 不重新摆姿势、不停顿、不先“保持当前姿势一秒”。
- 第一秒内保持首帧光线、构图、动作方向和人物左右关系。

**画面是静止站位或对峙：**

优先从小而可信的运动开始：

- 视线变化；
- 呼吸；
- 手部或身体重心变化；
- 头发和衣物受风或动作响应；
- 环境中的合理动态。

避免从静止图第一帧直接瞬跳到无关大动作，导致身份和构图漂移。

### 4.4 区分主体和镜头

分别写：

```text
主体如何运动：
镜头如何运动：
环境如何响应：
```

一段中至少有一个层级保持稳定。主体动作复杂时，镜头应更克制。

### 4.5 设计落点

说明：

- 人物最终姿态；
- 镜头最终景别；
- 道具和场景状态；
- 光影是否保持；
- 声音如何结束。

---

## 5. 首帧、尾帧和关键帧

### 只有首帧

重点写“从当前画面接下来发生什么”。

### 只有尾帧

反推一个自然可达的动作路径，不擅自改变目标画面核心状态。

### 首帧 + 尾帧

检查：

- 身份和服装是否一致；
- 场景和光线是否连续；
- 动作在时长内是否可达；
- 镜头位置变化是否合理；
- 是否需要中间关键帧或拆镜。

### 多张关键帧 / 分镜

每张图对应一个动作阶段或镜头状态，按顺序明确承接，不把所有图片混成一个画面。

---

## 6. 时间轴策略

默认按 **15 秒生产单元** 规划。用户未指定时长时不写更长片长。

简单动作可用自然顺序描述。

动作复杂、一镜到底或持续攻防时，使用 3–4 个 Beat，而不是每 1–2 秒一个独立动作盒：

```text
0–3 秒：从首帧状态进入第一轮可读动作
3–8 秒：主交换 / 主运动
8–13 秒：高潮或 Signature
13–15 秒：从最后状态收束，保持张力
```

这是密度示意，不是固定秒表。Beat 之间必须继承姿态、动量、接触和环境状态，禁止每段重新起架。

全局继承清单只出现在开头；各 Beat 只写本段变化。不要按时间段重复图片静态细节。

## 9. 常见失败

- 大量复述静态图片，运动描述过少；或反过来完全不锁首帧继承项；
- 把动作中点图写成重新起架；
- 把 15 秒任务写成 20–30 秒时间轴；
- 图片职责不清；
- 多张图片平均融合；
- 人物动作和镜头运动同时过强；
- 起始动作过猛导致变脸和构图漂移；
- 首尾帧在目标时长内不可达；
- 无原因增加人物、道具或场景；
- 忽略原图光源和风格延续。

---

## 10. 模型适配

- Generic：使用语义化的参考图职责描述。
- Seedance 2.0：转换为明确的 `@图片N` 职责绑定。
- LTX-2.3：少写已可见静态信息，重点描述从静止到运动、镜头跟随和声音出现。
